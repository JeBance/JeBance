# 🧩 Единый стиль коммитов
Универсальный стандарт для всех проектов

Этот документ описывает единый стиль коммитов, используемый во всех проектах. Он обеспечивает читаемость, техническую точность и единообразие истории разработки.

---

## 1. Формат заголовка

Заголовок всегда оформляется так:

`
<type>: <краткое действие в 2–5 словах>
`

Допустимые типы:
- feat — новая функциональность  
- fix — исправление ошибки  
- refactor — переработка без изменения поведения  
- style — визуальные правки (CSS, UI)  
- chore — обслуживание проекта, структура, пути, конфиги  
- docs — документация  
- release — релизы и версии  

Правила заголовка:
- коротко и по делу  
- без точки в конце  
- только действие, никаких лишних слов  

---

## 2. Тело коммита

Тело коммита обязательно многострочное и оформляется в виде bullet‑пунктов:

```
- что изменено
- почему изменено (если важно)
- технические детали (если есть)
```

Правила:
- каждый пункт — отдельная строка  
- никаких длинных абзацев  
- только структурированные bullets  
- техническая конкретика приветствуется  

---

## 3. Переносимость путей

Если изменения касаются структуры проекта, путей или сборки, обязательно указывать:

```
- настроены относительные пути ./assets/css и ./assets/js
- улучшена переносимость проекта
```

Это гарантирует, что проект можно переносить между окружениями без проблем.

---

## 4. Примеры коммитов

Новый функционал
```
feat: добавлен модуль генерации токенов

- реализована функция createToken()
- добавлена валидация входных параметров
- модуль изолирован и не зависит от внешних библиотек
```

Исправление ошибки
```
fix: устранён баг в обработке формы

- исправлена проверка пустых значений
- обновлена логика валидации
- добавлены тестовые данные
```

Рефакторинг
```
refactor: упрощена архитектура модуля запросов

- вынесены вспомогательные функции в utils/
- снижена вложенность условий
- улучшена читаемость кода
```

UI / CSS
```
style: обновлены стили интерфейса

- улучшены отступы
- обновлена типографика
- оптимизированы цвета
```

Структура проекта
```
chore: реорганизована структура директорий

- упорядочены assets
- удалены устаревшие файлы
- настроены переносимые относительные пути
```

Релиз
```
release: v1.2.0

- улучшен UI
- добавлены новые функции
- исправлены ошибки
- оптимизирована производительность
```

---

## 5. Итоговый принцип

Короткий заголовок + структурированное тело + техническая точность + переносимость.

Этот стиль делает историю разработки:
- чистой  
- понятной  
- профессиональной  
- единообразной  
- удобной для работы на смартфоне
